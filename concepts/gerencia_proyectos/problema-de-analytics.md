# Problema de analytics

## Idea principal

El problema de analytics es la traduccion del problema de negocio a un enfoque analitico viable. No se trata solo de elegir una tecnica; trata de definir que resultados se desean obtener, que restricciones existen, que metricas muestran exito y que tipo de analisis puede responder a la necesidad del negocio.

## Elementos centrales

El punto de partida es el problema de negocio ya definido. A partir de alli se reformula la pregunta en terminos de analytics, pasando del "que" del negocio al "como" del analisis.

Se buscan responder preguntas como:

- ¿Que resultados se desean obtener?
- ¿Quienes participan o se ven afectados?
- ¿Que cambios esperados genera la informacion?
- ¿Que restricciones o limitaciones existen?
- ¿Que datos y recursos son necesarios?

La traduccion suele hacerse con objetivos generales y objetivos especificos. Cada objetivo debe ser claro, medible y alcanzable, y debe estar alineado con la realidad organizacional: datos disponibles, capacidad tecnica, tiempos y stakeholders.

## Metricas y criterios de exito

Para cada objetivo se deben definir metricas que permitan evaluar si la solucion aporta valor. Estas metricas pueden estar relacionadas con:

- productividad o eficiencia
- calidad de la decision
- reduccion de costos
- mejora del servicio o del producto
- riesgo operativo o financiero

El exito de un proyecto de analytics no se mide solo por un modelo preciso, sino por su capacidad para resolver un problema real y ser implementado dentro de la organizacion.

## Tecnicas y exploracion de viabilidad

Antes de elegir una tecnica especifica, conviene tener una idea general del tipo de analisis que puede resolver el problema:

- analisis descriptivo para comprender comportamiento previo
- algoritmos supervisados para predecir eventos o clasificar resultados
- algoritmos no supervisados para segmentar o detectar anomalias
- NLP o analisis de texto para explorar contenido no estructurado
- analisis de decision para apoyar estrategias operativas

Esto ayuda a identificar si el problema es viable desde el punto de vista de datos, infraestructura y capacidad de ejecucion. Si faltan datos relevantes, si la informacion no es accesible, o si el problema no puede modelarse de forma razonable, debe reformularse antes de continuar.

## Herramientas utiles

El modelo Kano ayuda a distinguir entre requerimientos esperados, desconocidos y agradables para los clientes. La Casa de la Calidad (QFD) permite relacionar necesidades del cliente con caracteristicas tecnicas o de servicio, mostrando prioridades y trade-offs.

En la practica, estas herramientas permiten sistematizar la informacion antes de empezar a construir la solucion.

## Proceso general

1. Definir el problema de negocio y los interesados.
2. Reformularlo como un problema de analytics.
3. Establecer objetivos, restricciones y beneficios esperados.
4. Identificar datos, accesibilidad y factibilidad.
5. Definir metricas de exito y criterios de mediciion.
6. Obtener validacion de stakeholders.
7. Explorar tecnicas apropiadas para la solucion.
